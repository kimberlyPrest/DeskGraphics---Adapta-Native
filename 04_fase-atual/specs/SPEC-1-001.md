# SPEC-1-001 — Fundação: Modelo de Dados, Fixture e Auth

**Fase:** 1 · **Levas:** A (T1.1, T1.2, T1.3) e D (T1.12) · **CAs:** CA-1-01..06

## Objetivo
Construir a fundação do sistema SEM nenhuma dependência de integração: modelo de dados central do funil, fixture sintética e autenticação com perfis.

## Escopo
- **T1.1** — Fixture sintética: leads com origem/campanha/peça, SQLs, estágios, vendas/perdas com motivo (sem PII real)
- **T1.2** — Modelo de dados: lead (origem, campanha, peça, datas), estágio (histórico com timestamps), venda (valor, data), perda (motivo)
- **T1.3** — Auth + perfis: login, papéis admin/gestor/sdr/leitor, proteção de rotas
- **T1.12** — Revisão de segurança: auth, segredos, PII, regras de acesso

## Critérios de aceite
- **CA-1-01** — Fixture sintética carrega no modelo sem erro e sem PII
- **CA-1-02** — Modelo registra histórico de estágios com timestamps (não só estado atual)
- **CA-1-03** — Login funciona; rotas protegidas redirecionam para login
- **CA-1-04** — Papéis admin/gestor/sdr/leitor com permissões distintas (prova server-side)
- **CA-1-05** — Nenhum segredo em prompt ou repositório
- **CA-1-06** — Revisão de segurança da fundação aprovada (auth, PII, acessos)

## TDD
- **RED:** modelo sem histórico de estágios falha; rota protegida sem login redireciona
- **GREEN:** fixture carrega; auth/perfis operam
- **REGRESSÃO:** re-carga da fixture não duplica

## Dependências
- **Nenhuma** — fundação pura, sem API
